# Повседневные ответы, инженерия и код: проверка и выпуск 2026-11-04

Изменения установлены на сервер. Это измерение на ограниченном наборе задач, а не доказательство равенства ChatGPT/Claude или безошибочности на любых запросах.

## Что изменилось

- Исправлена порча C#-кода фильтром секретов: выражения вроде `linkedCts.Token` больше не заменяются на `•••`. Настоящие значения сохранённых секретов скрываются независимо; строковые секреты по-прежнему распознаются.
- Языки C++, Rust, C#/.NET, Cortex-M0 и Enfusion теперь распознаются как код и получают требования к границам, ошибкам, владению, отмене и полноте реализации.
- Самодостаточный запрос «только код/JSON» проходит без планировщика и каталога ненужных инструментов. Работа с проектами, файлами, запуском и проверкой источников сохраняет обычный маршрут. «Источники отмены» не путаются с источниками информации.
- Для короткого кода с асинхронностью и отменой выбирается один Sol в пределах тарифа (Terra, если Sol недоступен). Для линейных алгоритмов с явным ограничением памяти выбирается Terra; обычные функции остаются на Luna. Это адресное усиление, не повышение модели для всего кода.
- Личные бытовые обстоятельства не превращаются в веб-поиск из-за слова «сегодня». Сокращение текста должно сохранять условия, время и контакты; рецепты учитывать названные продукты.
- Дополнены инженерные правила для кручения: неизвестную геометрию/материал нельзя подменять кругом/сталью; крутильная постоянная не равна полярному моменту для произвольного сечения. При явно отсутствующих данных даётся прямое объяснение, без бессмысленного вычисления.
- Ограниченные числовые инженерные расчёты с JSON идут через одного автора Sol и инструмент `calculate`, без планировщика файлов. Модель выбирает физическую формулу; инструмент проверяет арифметику. Действия с файлами/аккаунтами, источники, реальные заключения о безопасности и явно отсутствующие данные исключены. Маршрут отдельно подключён для постоянных облачных задач; рабочие проекты и возобновляемые журналы сохраняют обычный путь.
- Добавлены проверенные сведения об ARMv6-M и небольшой справочный фрагмент API Arma Reforger: у `ScriptComponent` удаление — `OnDelete(IEntity owner)`.

## Проверка кода

- Python 3.12: интервалы с касанием границ, ленивые генераторы и бесконечный вход, порядок/параллелизм и очистка дочерних задач при ошибке и отмене.
- C++17: строгий разбор int32 с границами/неверным вводом, максимум окна с эталонным сравнением на случайных входах, стабильное удаление отрицательных нечётных чисел. Компиляция и UBSan, включая `INT32_MIN` и пустые входы.
- Rust 1.85: разбор чисел, переполнение со сохранением всего исходного HashMap, вставка нулевого значения, generic без Clone/Copy, Unicode с байтовым смещением.
- Cortex-M0: компиляция объектов `-mcpu=cortex-m0 -mthumb -fno-exceptions -fno-rtti`, плюс проверка unsigned wraparound и восстановления PRIMASK на хосте с явной моделью CMSIS. Это не запуск прошивки на реальном MCU и не проверка аппаратных таймингов/полной линковки.
- C#/.NET 8: однопроходные IEnumerable, пустой/null/крайние значения; связанная отмена, собственный таймаут, завершение дочерней операции, сохранение синхронной ошибки и ошибки очистки, корректность положительного таймаута 30 дней. SDK запускался без сети и NuGet restore.
- JavaScript ES2022: порядок и предел параллелизма, ошибка без запуска новых элементов и ожидание уже начатых, недопустимый limit; SQLite — NULL в подзапросе и клиенты без заказов.

Генерируемый код запускался в отдельных контейнерах: без сети, без секретов приложения, с пользователем без привилегий, ограничениями памяти/процессов/времени и исходниками только для чтения. Это проверка сохранённых ответов, а не обещание автоматической компиляции каждого будущего ответа пользователю.

## Инженерия, бытовые ответы, Enfusion

В наборе 8 инженерных задач: 6 с числовым JSON и 2 с недостатком данных. Проверяются учебная балка, кручение круглого вала, нагруженный делитель, RC-фильтр, параллельные резисторы и стационарная тепловая модель. Расчётные модели заданы в заданиях; эта проверка не подтверждает безопасность реальных конструкций.

8 бытовых задач проверяют готовые сообщения без выдуманных обещаний, сохранение контекста/контакта, ограниченные продукты, посильные бытовые шаги и отсутствие чтения чужих мыслей. Автоматические проверки объёма и ключевых условий дополнены чтением ответов. Лексическое прохождение не означает, что все нюансы смысла сохранены идеально; остаточные замечания записаны в `manual-review.json`.

Enfusion: проверены сигнатуры по первичной документации, парность CallLater/Remove, Insert/Remove и логика повторных Start/Bind. **Компилятора/Workbench Enfusion на сервере нет**: компиляция и исполнение внутри Reforger не проверялись. Правильный основной ответ не исключает ошибочных дополнительных пояснений; это отдельно учитывается при чтении.
