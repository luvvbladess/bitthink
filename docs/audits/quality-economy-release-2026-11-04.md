## Что изменено

- **Устранена порча правильного кода.** Очистка ссылок принимала индексы `[0]`, `[1]` за номера источников. Правильный `shallow[0].append(3)` превращался в неверный `shallow.append(3)`. Теперь блоки кода, inline-код и JSON защищены при очистке и разрешении ссылок. Типографика также не изменяет значения JSON и строки внутри кода.
- **Один исполнитель для ограниченного ответа.** Обычный разбор не обязан проходить отдельный выбор задания, планировщика, сотрудника и сборщика. Короткий веб-вопрос может вести один агент, который читает источники и отвечает. Проекты, вложения, действия с файлами и аккаунтами, расчёты, поиск товаров и сложные операции сохраняют обычный путь.
- **Сильная модель получает меньше лишнего контекста.** Для предметного анализа сохраняется доступный тарифу Sol. Сокращается только точный стандартный промпт приложения, без удаления пользовательских правил, памяти, истории и ограничений безопасности. Чужие системные сообщения не обрезаются. При активном проекте короткий маршрут не отключает инструменты.
- **Предметные инструкции работают в обоих режимах.** История, гуманитарный разбор и код получают требования проверять предпосылки, отличать факт от интерпретации, не выдумывать цитаты и результаты запуска.
- **Чтение страниц ищет нужные определения.** Учитываются API-идентификаторы и якорь URL; выбираются дополняющие фрагменты вместо преобладания повторяющейся навигации. В ответ передаются реальные фрагменты с позициями, без дополнительной модели.
- **Строгий JSON.** При явном требовании удаляется только полная Markdown-обёртка вокруг действительно разбираемого JSON. Данные и отсутствующие поля не угадываются.

В продукт не добавлялся общий модельный критик, дообучение или исполнение сгенерированного кода ради каждого ответа. Ограниченные исполнительные проверки примеров остались инструментом аудита.

## Проверка качества

Claude Sonnet 5.5 через OpenRouter сравнил ответы вслепую на 11 содержательных задачах каждого режима: порядок A/B случайный, названия версий скрыты. Приоритет — правильность, ограничения, полнота и отсутствие выдумок; длинный ответ не считается автоматически лучшим.

| Режим | Предпочтение новой версии | Исходной | Ничья |
|---|---:|---:|---:|
| Экспресс | 10 | 1 | 0 |
| Оркестратор | 10 | 0 | 1 |

Это вспомогательная модельная оценка, не независимая человеческая экспертиза и не процент истинных ответов. В одном литературном разборе оценщик предпочёл исходную версию: трактовки в ней были чётче разведены. Проверенность всех ссылок он без полных исходных страниц не аттестовывал. В двух ответах оценщика перед JSON присутствовал текст; единственный объект с нужной схемой извлечён из сохранённого ответа без повторной оценки и изменения вердикта. Стоимость этих двух вызовов оценщика сохранилась не полностью.

Отдельная проверка исполнила SQL на клиентах без заказов, неоплаченных заказах и одинаковых суммах разных заказов. Итоговые запросы корректны в обоих режимах; исходный Экспресс нарушил строгий JSON в одном контрольном SQL-ответе. Примеры `copy` исходной версии и V5 имели несогласованный вывод после обработки ссылок; в V6 индексы сохранены, исполненные примеры дают указанный результат. Также проверены JSON извлечения, отсутствие выдуманного срока, календарные стили, ложная предпосылка, вымышленная цитата и продолжение диалога.
