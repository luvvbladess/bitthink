# Оркестратор: соразмерные правки кода — 5 ноября 2026

Установлено на сервере **5 ноября 2026, 03:13 МСК**. Логика общая для веб-Оркестратора и режима director в Bit Client. Новый установщик не требуется: локальные файловые инструменты клиента не менялись.

## Что изменено

- Планировщик больше не обязан разделять задачу только потому, что в ней есть несколько шагов. Чтение, патч и проверка одного участка принадлежат одному исполнителю. Параллельное редактирование общих файлов запрещено; независимые результаты по-прежнему можно выполнять параллельно.
- Для явно заданной локальной правки добавлен ограниченный маршрут: один обычный исполнитель, без отдельного классификатора/планировщика. Это не автоматическое назначение дорогой модели по слову «код». При ошибке или отсутствии подтверждения задача возвращается к обычному планированию с сохранённым журналом.
- Короткий маршрут действует для одного-двух явно названных исходных файлов или конкретной правки подписи/опечатки. Не применяется к связанным облачным продуктам, изображениям, CAD, рискованным операциям, SDK, миграциям, безопасности, развёртыванию, внешним действиям и явно широким переделкам. Для остальных задач сохранён прежний маршрут.
- Исполнитель получает короткие инструкции и только подходящие инструменты. В облаке — Linux и workspace_run с argv, в клиенте — Windows/PowerShell и desktop_run_command. Внешние коннекторы не добавляются в каталог мелкой правки.
- В инструкциях кода уточнено: сохранять существующие API, стиль и зависимости; не добавлять фабрики, слои, интерфейсы и реорганизацию ради SOLID/DRY или будущих задач. Явно заказанный рефакторинг и необходимое устранение причины ошибки остаются допустимыми. Целевая проверка предшествует расширению проверок; обязательные правила проекта сохраняются.
- У единственного исполнителя больше нет инструкции опрашивать несуществующих коллег. Идентификатор исполнителя, журнал и события интерфейса сохраняются; для нескольких исполнителей обмен остаётся.
- Успешное завершение короткого маршрута требует наблюдаемой записи workspace_write/workspace_edit и успешной проверки после неё. Новая запись сбрасывает подтверждение; ошибочная запись его блокирует. Непройденная проверка не перекрывается успехом другой команды. Добавлено распознавание unittest, compileall, node --test, cargo/go/dotnet build/check/test, ctest и cmake --build в соответствующем существующем механизме.
- После подтверждённой работы одного исполнителя его ответ используется непосредственно, без повторной модельной сборки. Заявления модели «готово» сами по себе не дают этот путь. Лимит короткого исполнителя — 12 ходов с инструментами, общие ограничения раундов и тарифа сохраняются.

Изменены пять файлов приложения: services/code_change_policy.py, services/orchestrator_policy.py, services/desktop_swarm.py, bot_core/director_router.py и bot_core/computer_skills/code/SKILL.md. Добавлен отдельный тестовый модуль и воспроизводимый оценочный сценарий backend/evals/code_edit_calibration.py.

## Bit Client: публичный WebSocket и настоящие инструменты Windows

Использованы одноразовые Pro-аккаунты и новые локальные каталоги. Запросы прошли через публичный /api/desktop/ws; выполнялись реальные executeLocalTool из исходников текущего Bit Client и команды Windows. Проверялся транспорт и локальный исполнитель, без автоматизации визуального интерфейса.

- Старая версия: скидка — 43,228 с; изменяемый список — 22,840 с. Третий запрос о границе лимита изменил исходник, но не вернул финальное завершение за 240 с; он не засчитан как завершённая задача. Полного трассирования последнего зависания нет, поэтому его нельзя уверенно приписать одной конкретной стадии или провайдеру.
- Обновлённая логика: все три задачи завершились; 22,191 / 24,764 / 23,967 с. Независимые unittest прошли, защищённые файлы не изменились. Одна задача оказалась немного медленнее старой версии; общего гарантированного ускорения не заявляем.
- После финальной установки сценарий с границей лимита ещё раз прошёл публичный WebSocket и реальные инструменты Windows: **25,157 с**, независимый unittest успешен, защищённые файлы сохранены. Протокол — client-postcheck.json; синтетический аккаунт удалён.

Первый клиентский стенд ошибочно считал служебную папку истории отката .bitclient новым пользовательским файлом. В нормализованном отчёте исключена только эта метка; исходные сообщения ошибки сохранены в harness_initial_errors. Тайм-аут не исключён. Первое удаление синтетического аккаунта сорвалось из-за закрытого SSH-соединения; добавлен keepalive/переподключение, оставшийся аккаунт удалён отдельно. Пользовательские аккаунты не затрагивались.
