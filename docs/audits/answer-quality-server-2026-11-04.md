# Серверная проверка качества ответов — 4 ноября 2026

Вывод: пакет не прошёл приёмку как общее улучшение качества и экономии. Есть точечные улучшения SQL и ссылок, но устойчивое превосходство не установлено; расходы выросли. Рабочий сервер не обновлялся.

## Метод

Базовая версия — точная копия работающего серверного образа. Кандидат — тот же образ с пятью точечными изменениями: routing.py, director_router.py, handlers/core.py, subject_guidance.py и новым answer_quality.py. Прочие локальные незавершённые правки не переносились. Хеши — manifest.json.

Изолированные одноразовые контейнеры с отдельными SQLite, uploads, data и синтетическими аккаунтами Creator. Секреты провайдеров использованы только на сервере; производственные БД, диалоги и пользовательские файлы не подключались. Контейнеры имели доступ к сети для реальных моделей и источников. Запросы не требовали отправок, публикаций и внешних записей.

12 одинаковых задач × 2 версии × 2 режима = 48 ответов. Три спорных задачи (SQL, JSON, документация) повторены в каждом сочетании: ещё 12. Всего 60. В каждом запуске не более двух запросов одновременно; версии запускаются последовательно. Основной порядок: исходный Auto, кандидат Auto, кандидат Director, исходный Director. Повторы в том же порядке. Кэш, порядок, сеть и вариативность модели влияют на цену и время.

## Содержательная проверка

- Гуманитарные ответы: обе версии обосновывают трактовки текстом. На этих примерах убедительного общего преимущества нет.
- Ложная историческая предпосылка и вымышленная цитата: обе версии отвечают корректно.
- Исправление Python-функции: извлечённые исправленные функции обеих версий реально исполнены на независимых вызовах и переданном пустом списке; проверки проходят.
- SQL: запросы исполнены в SQLite на таблицах с NULL и повторяющимся blocked.user_id. В исходном Auto первый ответ содержит ложное предупреждение о дублях при антисоединении; повторный ответ содержит дополнительный запрос с несуществующим алиасом b. У кандидата полные SELECT-запросы проходят проверку.
- JSON: обе версии Auto сначала выдают Markdown-обёртку, в повторе обе дают строгий JSON. Оркестратор выдаёт строгий JSON в обоих прогонах обеих версий. Исправление Auto не подтверждено.
- Ссылки: исходный Auto сначала не даёт запрошенных ссылок на документацию; кандидат даёт. В повторе ссылки есть у обеих версий. Наличие URL само по себе не доказывает поддержку каждого утверждения.
- Оркестратор с кандидатом в первом веб-разборе признаёт, что не прочитал нужный раздел и не подтверждает существенное утверждение; исходный ответ полнее. Это регресс полноты, несмотря на осторожный тон.
- Кандидат Auto в вопросе о версии Python добавляет непрошенные сведения о безопасности и рекомендации по установке. Версия сверена с официальной страницей https://www.python.org/downloads/; все дополнительные утверждения отдельно не аттестованы.

Ручная оценка выполнена тем же агентом, который делал изменения; она не слепая и не независимая. Полные ответы сохранены для повторной проверки. Единого численного «процента качества» намеренно нет.

## Автотесты и точность измерений

Кандидат: 131/131 серверных проверок прошли. Исходная версия: 122/126 — четыре ошибки относятся к новым требованиям по маршрутизации кода и экономичному переводу. Это ожидаемая разница поведения, не оценка истинности ответов.

Две проверки test_orchestrator_hardening исключены у обеих версий: test_bot_report_preserves_stored_per_call_cost_and_legacy_estimates требует внешнего botneiro/web_usage.py; test_cost_migration_preserves_legacy_rows_and_is_reversible требует каталога alembic вне смонтированных тестов. Первоначальные ошибки окружения обнаружены и разобраны. Итоговый JUnit содержит результаты после исключения, без маскировки этих двух ограничений.

Дополнительно локально прошли 129 проверок test_chat_understanding.py и test_answer_quality.py после изменения сборщика метрик.

Обнаружено: исходный evals/chat_understanding.py теряет вложенные trace-id Оркестратора и сообщает нулевую стоимость. В этом аудите общие расходы и вызовы восстановлены из всех orchestrator_call в отдельном журнале каждого контейнера. Нулевые per-case metrics Director в сырых results.json недостоверны; для сумм используйте analysis.json поля trace_cost/trace_calls. Точная привязка расходов к отдельному запросу Director в этом прогоне не восстановлена. Локальный сборщик исправлен через ContextVar для следующих запусков; текущие прогоны обеих версий использовали один и тот же исходный сборщик.

## Решение и следующий пакет

Не выкладывать весь кандидат как доказанное улучшение. Следующие отдельные изменения: строгий выходной формат с проверкой JSON; чтение релевантных разделов документации вместо многократных малополезных фрагментов; ограничение повторов без нового свидетельства; повышение модели только по содержательной сложности; сокращение дублирующихся инструкций.

Перед приёмкой следующего пакета нужны новые контрольные примеры и повторное сравнение. Этот аудит не охватывает CAD, большие репозитории, вложения, длинные диалоги, нагрузку и все тарифы; не является сравнением с интерфейсами ChatGPT, Claude и Perplexity.
