# Рабочая область проекта

Проекты доступны в боковом списке чата. Выбор открывает личную беседу проекта и материалы рядом на широком экране; на узком экране материалы занимают основную область с возвратом к беседе. Можно развернуть материалы на всю ширину. Оркестратор, Экспресс и Студия сохраняют названия и автоматический выбор моделей.

Материалы, результаты и память разделены внутри рабочей области. Переключение использует короткий переход и движущийся индикатор; prefers-reduced-motion отключает движения. Редактор и удаление работают в той же области, без отдельного окна. Создание проекта — встроенная форма. Общие беседы не подключаются к частным материалам.

## Постоянные результаты

Таблица, текстовый отчёт и структурированные слайды сохраняются с ID и оптимистической версией в существующем хранилище проекта. UI позволяет править ячейки/текст/слайды и скачивать настоящий XLSX/DOCX/PPTX. История позволяет просматривать и восстанавливать версии. Изменение одной части сохраняет остальные ID и данные. Формулы из текстовых ячеек не исполняются при экспорте XLSX.

Инструменты: project_result, project_result_read, project_result_patch. Пагинация чтения выдаёт next_offset и явные метки укороченных ячеек; частичный spec нельзя использовать как полный объект. Для правок требуется expected_revision. Повторное создание идентичного результата моделью дедуплицируется. Фоновые изменения покрыты существующими квитанциями действий.

Обычная итоговая Markdown-таблица сравнения или текстовый отчёт может сохраняться автоматически без дополнительного обращения к модели, если задача относится к подключённому проекту и инструменты не создали результат в этом ходе. Это структурирование ответа, не дополнительная проверка его фактов. Сложные таблицы с объединёнными ячейками, полная совместимость редактора Office и свободное редактирование произвольной PPTX-вёрстки не заявляются. Структурированные слайды экспортируются в собственном простом оформлении.

## Материалы

Загрузка через рабочую область использует существующий разбор документов и ZIP. Извлечённые документы публикуются в проект. Доступный оригинал до 64 МБ копируется в приватный DATA_DIR/project-originals, который уже сохраняется между перезапусками контейнера. Несколько документов одного архива используют одну копию исходного ZIP. Оригинал скачивается через защищённый API с проверкой владельца и не находится в публичном uploads.

Удаление исходного вложения не удаляет копию проекта. Удаление материала очищает его историю, индекс и ссылку на оригинал; последняя ссылка удаляет общий файл. project_file_open переносит собственный оригинал в облачную песочницу через существующий защищённый транспорт, чтобы работать с исходными PDF/таблицами в новой беседе. Он не предоставляет локальные файлы чужого пользователя и не доступен вместо локальных инструментов BitClient.

Текстовые правки материала относятся к извлечённому тексту. Сам оригинал этим редактором не изменяется. Поиск остаётся лексическим по сохранённым фрагментам; полноценный индекс эмбеддингов в этот выпуск не включён. Начальная рабочая область показывает до 300 последних записей, инструменты поиска работают с индексом проекта отдельно.

## Пилот закупки

project_purchase_plan создаёт сохраняемую таблицу для 1–20 позиций. Это не подтверждение наличия. Оркестратор ищет конкретные предложения малыми пачками; после чтения карточки project_purchase_offer принимает дословные цитаты о цене и наличии, проверяет их в наблюдавшемся тексте, фиксирует URL и время. Если задан точный буквенно-цифровой артикул, он должен встречаться в тексте. Цитата о недоступности отмечается отдельно. Ранее сохранённые наблюдения остальных строк сохраняются вместе со старым временем проверки.

Нужно дополнительно проверять корпус, количество в упаковке, допустимость аналога и доставку. Совпадение цитаты не является полной семантической проверкой совместимости и не заменяет окончательную цену заказа. Планы можно продолжать по сохранённым строкам; закупщик на 300 позиций, полноценная оптимизация корзин по магазинам, регистрация и оплата не заявляются этим пилотом.

## Проверка

Тесты изоляции владельцев, общих бесед, версий, частичных правок, экспорта, формульной инъекции, реальных цитат и сохранности оригиналов. UI проверен на 1440, 1024 и 390 пикселях в тёмной теме и на 1440 в светлой: переходы, правка строки, разворачивание, возврат, отсутствие переполнения страницы. Модельные результаты и цены в UI-проверке — явно обозначенные фикстуры. Схема БД остаётся 020.
