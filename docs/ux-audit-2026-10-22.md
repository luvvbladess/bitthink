# Bit-Think: аудит UX и надёжности — 22 октября 2026

## Дополнение: создание нескольких бесед

После сообщения пользователя воспроизведён пропущенный сценарий: повторное нажатие «Новый вопрос» возвращало первую пустую беседу вместо создания следующей. Тест до исправления получил одну беседу при ожидаемых двух.

Убрано переиспользование пустых бесед. Явные нажатия создают разные беседы; запросы выполняются в порядке нажатий, позднее завершение не отменяет последующий выбор пользователя. Ошибка создания показывает понятное сообщение и не блокирует повтор; очередь прекращается при выходе из аккаунта. Работа другой беседы не блокирует создание новой. Привязка прежней пустой беседы к проекту больше не меняется ради её переиспользования.

Проверены семь новых браузерных сценариев, включая мобильное меню, быстрые нажатия и отправку второго вопроса при незавершённом первом. Полный клиентский набор из 25 сценариев прошёл до добавления финальной защиты выхода из аккаунта; после неё повторены все семь новых сценариев и TypeScript. Серверная проверка четырёх одновременных запросов подтверждает разные ID, сохранность всех пустых бесед и одну активную беседу; вместе со смежными тестами — 18 passed. Production-сборка исправления прошла. Изменения остаются локальными.

Проверен веб-проект Bit-Think: клиент React, API, история, работа с файлами, задания Оркестратора и обработка источников. Исправления внесены в рабочие файлы. На сервер изменения не публиковались. Существовавшие до аудита незакоммиченные изменения сохранены.

Размеры иконок действий с сообщением увеличены до минимальной области нажатия 44×44 на устройствах с coarse pointer. Поля входа получили autocomplete; вход, проверка аккаунта и refresh имеют ограничение ожидания.

Ограничение черновиков: бинарные вложения не сохраняются в sessionStorage. После полной перезагрузки вкладки текст восстанавливается, файлы нужно прикрепить заново. Хранилище черновика — sessionStorage текущей вкладки, а не серверная синхронизация черновиков.

Согласование react-is с версией React соответствует [инструкции MUI](https://mui.com/material-ui/getting-started/installation/#react-18-and-below). Это исправление зависимости, а не обновление UI-фреймворка.

## Почему изменились некоторые существующие тесты

Изменения ожиданий не заменяют исправления реализации:

- Проверка атомарного резервирования теперь заполняет действующий общий пятичасовой бюджет `session_tokens`, а не прежний бюджет одного режима. Реальный расход сверх порога сохраняется, как требует текущий общий учёт. Два конкурирующих запроса по-прежнему должны дать один успех и один отказ.
- В матрицу режимов добавлен действующий режим поиска; платный доступ к «Документам» не расширялся.
- Домены, написанные моделью в тексте, не должны автоматически становиться якобы проверенными источниками. Тест проверяет отсутствие вымышленных URL.
- Проверка закрытой страницы проверяет честное сообщение о том, что она не открылась, вместо устаревшей дословной подсказки модели.
- Проверка изоляции принимает либо реально заблокированное чтение, либо отказ запускать процесс без изоляции; утечка содержимого запрещена в обоих случаях.

## Что остаётся до заявлений о паритете с конкурентами

**P1: восстановление аккаунта.** В `LoginPage.tsx` прямо указано, что сброс пароля недоступен, но конкретного канала поддержки там нет. Пользователь с забытым паролем не может самостоятельно завершить сценарий. Нужен настроенный канал восстановления и продуктовый контакт; адрес поддержки не придумывался.

**Продуктовый разрыв: получение платного тарифа.** Лендинг и биллинг сообщают о выдаче доступа администратором и отсутствии онлайн-оплаты. Это действующее ограничение продукта, а не поломанная кнопка. Для самостоятельного массового сервиса понадобится завершённый путь покупки/продления и восстановления доступа.

**Проверка на устройствах.** Эмуляция viewport и touch не заменяет iPhone/Safari, Android с реальной клавиатурой, системным масштабированием, переключением приложений, записью микрофона и выгрузкой вкладки. Остановка дорожек проверена с тестовым MediaRecorder; реальное качество распознавания не оценивалось.

**Доступность.** Есть улучшения клавиатуры, фокуса и touch-целей; это не полная сертификация WCAG. Не выполнен полный автоматический axe-аудит и проход со скринридером, не проверены все состояния каждого редактора.

**Реальные ответы и эксплуатация.** Не выполнялись сравнительные платные запросы к Claude, Gemini, ChatGPT и Perplexity, оценка достоверности всех ответов, тест реальных подключений Gmail/MCP, нагрузочный тест production, проверки резервного копирования и развёртывание. На основании этого прогона нельзя обещать отсутствие всех лагов и багов или равенство качества ответов конкурентам.

Рекомендуемый следующий релизный проход: восстановление входа; покупка/продление доступа; физические мобильные устройства; полная доступность; замеры скорости на production; затем финальная полировка. Основные исправленные сценарии защищены воспроизводимыми регрессиями.

## Как повторить

Клиент: `npm ci` в `frontend`, `npm run typecheck`, `npm run build`. Для браузерных регрессий запустить `npm run dev -- --host 127.0.0.1 --port 5187`, затем `npm run test:ux` во втором терминале. Нужен установленный Chrome; адрес меняется через `BITTHINK_UI_BASE`, браузер — через `PLAYWRIGHT_CHANNEL`. Скриншоты пишутся в `test-results/ux` и исключены из Git.

Сервер: зависимости `backend/requirements.txt`, отдельные `DATABASE_URL`, `DATA_DIR`, `UPLOAD_DIR`, непустой тестовый `SECRET_KEY`; создать каталоги данных и вложений, затем `python -m pytest` из `backend`. Не использовать пользовательскую базу для тестов.

Журналы этого прогона: `tmp/ux-backend-tests-final.log`, `tmp/ux-browser-tests-final.log`, `tmp/ux-frontend-build-final.log`, `tmp/ux-extended-browser.log`. Эти локальные файлы не входят в Git.
