# Ответ без блокирующей проверки источников

Причина повторного инцидента: исправление от 26 октября сделало размещение ссылок рекомендательным только при наличии прочитанной страницы. Другие эвристики по-прежнему запускали дополнительный модельный проход, а затем `supported_partial` мог удалить готовый ответ целиком. Число источников в панели никак не предотвращало эту замену.

По запросу владельца продукта блокирующий этап удалён из `get_smart_response`, а не дополнительно ослаблен:

- нет повторного вызова модели для проверки источников после генерации;
- нет удаления абзацев или замены ответа заглушкой из-за количества ссылок, их размещения или статуса чтения страницы;
- поисковый ответ принимается без обязательного списка источников; пустой ответ, ошибка провайдера и текст псевдовызовов инструментов по-прежнему запускают штатный резервный маршрут;
- реальные источники, их история и преобразование явных сносок сохраняются для интерфейса;
- инструкции модели сокращены: использовать уже полученное содержимое без повторной проверки ссылки, отвечать по существу, не придумывать отсутствующие цены, наличие и даты, обозначать конкретные пробелы;
- правила доступа, ограничения инструментов и обработка ошибок самого провайдера сохраняются.

Диагностические функции в `source_quality.py` и прежний `kimi_result_is_grounded` оставлены для автономных тестов; в пользовательском маршруте они больше не вызываются. Это изменение не обещает автоматической проверки истинности фактов. Поиск нужной информации остаётся частью ответа на актуальные вопросы. Специализированное чтение карточек товаров для получения цен этим исправлением не заменяется.

Регрессии покрывают семь режимов (Авто, Поиск, Исследование, Экспресс, Песочница, Оркестратор, Студия) при четырёх вариантах источников: прочитаны, только найдены, чтение не удалось, список пуст. Полезный ответ сохраняется, отдельная проверка не вызывается. Дополнительно проверены ответы без ссылок и резервный маршрут при ошибке провайдера/псевдовызовах инструментов.

Сохранённые старые ответы не переписываются: для исправленного результата нужно повторить запрос. Схема базы, интерфейс и клиентское приложение не меняются.
