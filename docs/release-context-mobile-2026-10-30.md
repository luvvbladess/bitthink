## Что опубликовано

- Предпросмотр документов из ответа и библиотеки, масштаб и страницы, скачивание и системная отправка файла. На телефоне — полный экран, на компьютере — изменяемая ширина панели. Такой же размер панели доступен Студии.
- Удобные области нажатия, перенос строки по Enter на сенсорном устройстве, выбор камеры/фото/файла.
- Понятные действия облачного Оркестратора вместо внутренних названий инструментов, в том числе swarm_read/publish/send. Фоновые поручения показывают последнее действие; история не выдаёт смену статуса за доказательство успеха.
- Остальные накопленные изменения исходников: чтение страниц и визуальная проверка, браузерные инструменты, совместимость клиентов и провайдеров, обработка поиска и длительных соединений. Полный исходный выпуск проверен совместно.

## Контекст без зависимости от формулировки

Предыдущее локальное исправление определяло продолжение по словам и имени архива в тексте ответа. Оно заменено структурным механизмом:

1. Созданный продукт получает ссылку на рабочий проект в метаданных сохранённого вложения. Для старых результатов поддержан разбор имени именно сохранённого серверного вложения; текст сообщений и пользовательские вложения не создают такую связь.
2. На каждом ходе формируется каталог материалов только выбранной беседы. Он передаётся модели отдельно от сокращённой истории, поэтому исчезновение старой реплики из окна не уничтожает связь с проектом.
3. В облачном Оркестраторе существующий планировщик выбирает действие по смыслу сообщения и истории: изменить сохранённый проект, создать отдельный новый продукт или ответить на вопрос. Список разрешённых проектов передаётся сервером. Чужой идентификатор не принимается.
4. Перед правкой сервер проверяет доступность проекта для владельца, сохраняет новые требования и сбрасывает прежние подтверждения готовности. Новая версия требует новой проверки и упаковки.
5. Контекст передаётся через отдельную область выполнения и сбрасывается после запроса. Переключение открытой беседы не меняет файлы уже выполняющейся задачи. В общей беседе доступ к вложению не предоставляет гостю доступ к рабочей папке владельца.
6. Правила и отметка возобновления фоновой работы передаются как служебный контекст. Они больше не дописываются в сохраняемую пользовательскую реплику.

При недоступных исходниках показывается конкретная причина и путь восстановления из архива. Успех планирования не подменяет проверку результата; готовность определяется фактическими проверками.

## Проверки

- 158 браузерных сценариев Chromium: история, переключение/восстановление бесед, черновики, вложения, мобильная клавиатура, документы, Студия, тарифы, настройки и проекты. Необработанных исключений не обнаружено.
- В изолированном Linux/PostgreSQL окружении: 1163 серверных теста прошли, один тест пропущен. Дополнительно прошли финальные проверки контекста на собранном образе, включая сценарий без ключевых слов.
- Проверки качества: 137/137. Пользовательские сквозные сценарии: 5/5.
- На собранном образе выполнена настоящая конвертация Word, Excel и PowerPoint с кириллицей в предпросмотр; проверены текст и изображение страницы.
- После выкладки проверены публичные маршруты, контрольная сумма новой страницы, загрузка ресурсов, API и готовность исполнителя.
- Через настоящий API на временной учётной записи: две беседы сохраняют раздельные истории и контекст; Word открывается в предпросмотре; анонимное обращение и попытка открыть файл из другой беседы отклоняются.
- Реальный планировщик связал краткую просьбу сделать шрифты крупнее и добавить анимацию с текущим проектом. Вопрос о переработке лития выбрал обычный ответ без изменения проекта.

Физические телефоны не использовались: проверка экранной клавиатуры и системных действий на устройствах остаётся отдельной проверкой. Эти результаты подтверждают проверенные сценарии, а не безошибочное понимание любых будущих запросов.
