# Оркестратор Bit-Think: развитие по модели Perplexity

Название пользовательского режима остаётся **Оркестратор**. `director`, `/computer` и имена Python-классов — внутренние идентификаторы. Оркестратор BitClient с локальным доступом к проекту остаётся отдельной функцией.

## Что подтверждено первичными источниками

Perplexity Computer разбивает поручение на подзадачи, выбирает модели и инструменты, работает в облаке, создаёт результаты и поддерживает повторяющиеся задания: [страница продукта](https://www.perplexity.ai/en-GB/products/computer), [описание Computer](https://www.perplexity.ai/en-GB/hub/academy/what-is-perplexity-computer).

Навыки содержат повторно используемые инструкции. Пользовательские пакеты — Markdown либо ZIP с SKILL.md и YAML name/description: [Computer Skills](https://www.perplexity.ai/en-GB/hub/academy/how-to-use-computer-skills), [практическое руководство](https://www.perplexity.ai/en-GB/hub/workshops/perplexity-computer-for-buyside-professionals).

Custom MCP подключает внешние инструменты через удалённый HTTPS-сервер: [Getting started](https://www.perplexity.ai/en-GB/hub/getting-started). Реализация Bit-Think использует официальный [Python SDK MCP](https://github.com/modelcontextprotocol/python-sdk) и [Streamable HTTP](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports).

Публичная документация не раскрывает системные промпты, внутренний планировщик, алгоритм выбора модели и механизм hooks Perplexity. Правила рабочего процесса ниже — собственная реализация Bit-Think; утверждать совпадение внутренних механизмов 1 в 1 нельзя.

## Реализованные дополнения

* Постоянная очередь задач аккаунта в БД: однократный/отложенный запуск, повторение, пауза, отмена и продолжение по истории. Закрытие браузера не отменяет облачную работу.
* Журнал шагов и вызовов инструментов, ссылки на беседы с результатами, восстановление прерванной работы вручную. Просроченная аренда задачи не запускает её повторно автоматически.
* Серверный worker вызывает существующий многомодельный Оркестратор и использует текущие квоты. Доступ с Pro; тарифы и величины лимитов этим изменением не меняются.
* Удалённый MCP Streamable HTTP: публичный HTTPS, Bearer token, получение страниц tools/list, выбор разрешённых инструментов, вызовы tools/call. Токен хранится в зашифрованном подключении и не возвращается модели.
* Импорт/экспорт Markdown и ZIP навыков, хранение файлов ресурсов, чтение текстовых references из модели. Загруженные скрипты автоматически не исполняются. Лимит пакета 10 МБ, до 100 файлов и 64 000 символов инструкций.
* Декларативные правила: инструкции перед фоновой задачей, запрет определённых инструментов, ограничение объёма результата. Нет запуска произвольной команды hook или скрытой отправки HTTP-запроса.
* На сайте задачи, навыки, подключения и правила доступны из кнопки «Задачи и инструменты» под полем сообщения в режиме «Оркестратор». Панель раскрывается внутри блока ввода; длинные списки и формы имеют внутреннюю прокрутку. Отдельной страницы и пункта меню нет, старый `/computer` перенаправляет в `/chat`. В BitClient — общий раздел аккаунта «Оркестратор Bit-Think» с задачами, импортом/включением навыков и MCP. Обычная беседа клиента поддерживает облачный Оркестратор и Astra согласно тарифу.

## Ограничения текущего этапа

Это расширение существующего продукта, а не полный клон Perplexity. Пока не добавлены OAuth для произвольного MCP, MCP resources/prompts, транспорт stdio/legacy SSE, отдельный интерфейс Brain с происхождением каждого факта, интеграции Slack/Teams и полный каталог коннекторов Perplexity. Существующая память, голосовой ввод, браузерные инструменты, песочница, навыки и модельные сотрудники Bit-Think сохраняются, но не становятся побитовой копией соответствующих систем Perplexity.

В клиенте результат фоновой задачи открывается на сайте через текущий адрес API без суффикса `/api`; общая беседа также доступна через обычную синхронизацию чатов. Правила рабочего процесса на этом этапе редактируются на сайте.

## Проверка и выпуск

Backend: тесты очереди, изоляции владельцев, остановки/продолжения, защиты от устаревшего worker, правил, навыков и разрешённых MCP-инструментов; регрессия desktop/skills/tools. Frontend и BitClient: TypeScript и production build. Проверки моделей выполняются на фикстурах, без списаний с пользовательского аккаунта; доступ к реальному стороннему MCP требует подключения владельцем.

Перед выпуском установить backend dependencies, применить Alembic `018_computer_tasks`, пересобрать backend и frontend. Не заменять файлы серверной конфигурации VPN/nginx и не менять другие сервисы. Новые возможности требуют обновлённого сервера и сборки клиента; изменение исходников само по себе не публикует обновление.

Исходники BitClient изменены в `E:\progs\BitClient`. Оригиналы затронутых существующих файлов сохранены в `tmp/computer-backup-20261008` этого проекта.
