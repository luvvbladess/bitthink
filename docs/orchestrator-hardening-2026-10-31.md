# Обновление облачного Оркестратора — 31 октября 2026

## Установленные изменения

- Клиент OpenRouter сохраняет изображения пользователя, структурированную историю инструментов и непрозрачные блоки рассуждений. Поток собирается по индексам/идентификаторам, включая подписи и зашифрованные части.
- Изображения и файлы из доверенных результатов инструментов передаются дальше. Ошибочные аргументы инструмента не превращаются в пустую команду. Ошибка инструмента возвращается модели как диагностика с требованием проверить текущее состояние.
- Включены автоматический кэш Claude, идентификатор сессии для сохранения маршрута, обязательная поддержка параметров и запрет провайдеров, собирающих данные. Разрешённые уровни глубины берутся из реестра; high больше не заменяется на medium.
- Для продуктов OpenRouter поддерживает ту же остановку после подтверждённой готовности, что OpenAI. Повтор на другом провайдере разрешён только при подходящем техническом отказе до первого действия инструмента.
- Sonnet возвращён в рабочий пул и допускается на этапе сборки вместо Sol. Новый продукт сохраняет выбранного сильного исполнителя; Sol и Sonnet не нанимаются на дублирующую сборку. Astra исключена из обычной облачной ветки, специализированный CAD-путь сохранён. Nano исключён из общего пула исполнителей.
- В Auto сложная архитектура, доказательства и явно углублённая работа больше не отправляются в Haiku только из-за доступности OpenRouter. Haiku остаётся на ограниченных этапах.
- Короткий облачный вопрос без проекта пропускает предварительное планирование. Ранняя часть требований сохраняется при сокращении истории. Каждый исполнитель получает общую текущую цель и ссылки на проекты беседы.
- Большие документы передаются ограниченными фрагментами с указанием, как прочитать остальное. Объём выдерживается и при большом количестве файлов.
- Стоимость сохраняется как сумма отдельных вызовов, с приоритетом стоимости из ответа поставщика. Дневной и месячный отчёт больше не применяет порог Haiku к сумме коротких запросов. Исправлены длинные ставки GPT и случайное удвоение Sonnet/Opus/DeepSeek.
- Веб-отчёт расходов в сопутствующем боте (`botneiro/web_usage.py`) читает сохранённые суммы. Для старых записей без поштучной стоимости остаётся явно неполная оценка по базовым ставкам; точный исторический счёт из суммарных токенов восстановить нельзя.

## Управление расходами

`ORCHESTRATOR_MODEL_BUDGET_USD`: бюджет моделей облачного запуска, по умолчанию **$2**.

`ORCHESTRATOR_DESKTOP_BUDGET_USD`: бюджет моделей запуска BitClient, по умолчанию **$10**.

Резерв каждого вызова общий для параллельных исполнителей. При временной нехватке свободного резерва ожидается фактическое использование предыдущего исполнителя. Когда бюджет исчерпан, готовность незавершённой работы не объявляется, исходники и промежуточные результаты сохраняются.

Это бюджет вызовов моделей. Комиссии покупки кредитов, инфраструктура и отдельные платные сервисы в него не включены. Неизвестное использование после обрыва потока консервативно сохраняется в бюджете как неизвестный расход; это не подтверждённый счёт поставщика.

Для Responses вход считается через API подсчёта токенов также у безлимитного внутреннего пользователя. У Claude изображения резервируются как визуальные токены, а не как текстовая длина base64. Оценка текстового входа совместимых API остаётся консервативной.

## Модели-кандидаты

GLM 5.3 Flash и MiniMax M3.1 Flash доступны адаптеру и реестру, но **не включены в автоматический рабочий маршрут**.

Для ограниченного испытания: `ORCHESTRATOR_EXPERIMENTAL_MODELS=glm-5.3-flash,minimax-m3.1-flash`. Флаг не даёт доступа бесплатному тарифу и не меняет ручной выбор моделей. Цена экспериментального маршрута ограничивается на стороне OpenRouter. Для MiniMax при оценке используется пиковая ставка.

Ограниченная живая проверка выполняется отдельно:

```powershell
python -m scripts.selfcheck_openrouter
python -m scripts.selfcheck_openrouter --execute --budget-usd .30 --output router-check.json
```

Без `--execute` вызовов API нет. Используются только синтетическое изображение и чистый вычислительный инструмент, без доступа к пользовательским файлам. Проверка не включает модели автоматически.

Проверка на сервере:

| Модель | Вызов инструмента и продолжение | Изображение |
|---|---|---|
| Haiku 5.5 | Пройдено | Пройдено |
| Sonnet 5.5 | Пройдено | Пройдено |
| GLM 5.3 Flash, проверенный маршрут | Пройдено | Отказ провайдера |
| MiniMax M3.1 Flash | Пройдено | Пройдено |

Это проверка совместимости на двух случаях, не сравнение общего качества. GLM нельзя считать проверенным визуальным исполнителем. MiniMax требует отдельного набора продуктовых задач перед включением в основной маршрут.

## Проверки и установка

Пройдены **298 проверок** контракта OpenRouter, денежных резервов, расчёта расходов, контекста, создания продуктов, возобновления работы, биллинга и очереди поколений. Добавлены случаи для потери изображений, подписи рассуждений, ошибочных аргументов, сохранения файлов при отказе, параллельного бюджета и миграции старых записей. Отдельно проверен адаптер отчёта бота.

Миграция **024** добавляет `usage_records.estimated_usd` и `cost_is_complete`. Старые записи сохраняются. Обратимость миграции проверена на отдельной SQLite-базе; на сервере выполнено обновление PostgreSQL 023 → 024 после резервного копирования.

Backend и worker пересобраны и обновлены при отсутствии выполняющихся/ожидающих задач. Сервис отчёта бота перезапущен через его существующий PM2-процесс. Сайт отвечает 200, backend/worker имеют состояние healthy, отчёт бота читает базу успешно.

Настоящий короткий запрос через облачный Оркестратор завершился успешно: **один вызов модели, без предварительного планировщика, без ошибок**.

Телеметрия различает возврат из функции и подтверждённую приёмку продукта; записывает стоимость, её источник, провайдера и идентификатор генерации, если они доступны. Для обычного текстового ответа приёмка не выдумывается. Снижение стоимости успешно выполненной продуктовой задачи пока не измерено сравнительным испытанием.
