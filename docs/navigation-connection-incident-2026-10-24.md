# Переходы между разделами и потеря соединения

Проверка после жалобы на рабочий https://bit-think.space/. Время замеров сервера — 23 октября UTC, отчёт — 24 октября по Москве.

## Подтверждено

- `useWebSocket` находился в `ChatPage`: переход в настройки/кабинет закрывал сокет, возврат открывал новый. Браузерный тест на опубликованном коммите `61beffe` воспроизвёл лишнее подключение (2 вместо 1).
- Существующий heartbeat отправлял ping, но не ожидал pong с ограничением времени. Зависший TCP-канал мог оставаться в состоянии OPEN, хотя ответы уже не приходили.
- Состояние `open` выставлялось до подтверждения авторизации сервера.
- Код разделов загружался только при первом переходе. Отказ загрузки динамического модуля не имел обработчика ошибки и способа восстановления внутри приложения.
- Во время проверки наблюдались и внешние сетевые сбои: после нормальных ответов WebSocket 49–67 мс отдельные соединения/запросы переставали отвечать. В тот же период backend внутри сервера отвечал примерно за 2–3 мс; перезапусков и OOM не было. Проверка API и ресурсов с отдельного сервера давала HTTP 200. Источник внешней нестабильности этим не установлен; изменения интерфейса не гарантируют устранение проблем сети.

## Исправления

- Один `ChatConnectionProvider` владеет сокетом всей авторизованной сессии. Разделы подписываются на события, переходы не закрывают транспорт. После возврата чат получает сохранённую историю и актуальный снимок задач; старые chunk-события не проигрываются повторно.
- Ping каждые 10 секунд, ограничение ожидания ответа/готовности 15 секунд, немедленная замена зависшего сокета без ожидания закрытия TCP. Поздние события старого соединения игнорируются.
- Готовность соединения подтверждается сообщением `jobs`; только после него отправляется очередь сообщений. При отказе авторизации используется существующее обновление токена через HTTP.
- Возврат во вкладку и восстановление сети инициируют проверку соединения.
- Настройки и кабинет предварительно загружаются после входа и при открытии меню; ссылки также загружают целевой раздел при фокусе/наведении/касании.
- Ошибка раздела остаётся внутри `RouteErrorBoundary`: доступны повторная загрузка и переход в чат/настройки. Черновик не теряется.

- TypeScript и production-сборка прошли.

- Production-сборка: **5 passed** — сохранение соединения и черновика при переходах; восстановление молчащего сокета; выход из ошибки загрузки раздела; отсутствие повторного проигрывания ответа; восстановление ответа, завершившегося во время просмотра настроек.
