# Адаптация материалов Perplexity для БитСинк

Дата: 9 октября 2026. Источник — предоставленная папка «Материалы для заказчика»,
включая полный каталог исходников и руководство. Это адаптация описанных принципов,
а не воспроизведение закрытого исходного кода, ranking или внутренних промптов Perplexity.

## Что вошло в продукт

- 38 предметных рабочих инструкций с русскими названиями, узкими триггерами,
  отдельными справочниками и привязкой к настоящим инструментам.
- 8 личных шаблонов: добавляются владельцем аккаунта. До добавления не загружаются
  в промпт. Частные Drive-ID, авторские подписи, обязательный перенос материалов
  на чужой диск и противоречивые персональные правила исключены.
- Общий цикл Оркестратора: цель → ограничения → зависимости → выполнение →
  проверка изменённого состояния → результат. Независимые работники разделяют
  реестр наблюдений, а не объявляют собственный текст доказательством.
- Реестр фактических возможностей `get_capabilities`: наличие навыка отделено
  от подключённого сервиса, разрешения и успешного выполнения.
- `read_skill_resource` читает встроенные и личные текстовые ресурсы по страницам,
  учитывает выключение навыка, владельца, общий чат и безопасный путь.
- `task_create/task_list/task_control` используют прежнюю очередь, Pro-ограничения
  и проверку владельца. Одинаковые параллельные создания внутри одного хода
  дедуплицируются; после создания читается реальная запись. Фоновый запуск не
  создаёт вложенное расписание и не управляет собственным расписанием.
- Реестр источников хранит настоящий URL, время, статус чтения и извлечение
  текстов отзывов. Он попадает в синтез и панель источников. Статус чтения не
  является доказательством полного покрытия страницы или правильности вывода.
- Экспресс, Оркестратор, Студия и остальные действующие режимы сохранены.
  Названия провайдеров удалены из описаний режимов; выбор исполнителей внутренний.
  Новая отдельная страница не создаётся. Навыки и шаблоны встроены в существующие панели.

## Быстрый поиск с сервера

`WEB_SEARCH_BACKEND=server` — новый режим по умолчанию. Собственный HTTP-слой
получает публичную выдачу DuckDuckGo, при нехватке полезных результатов — Bing RSS.
Нет дополнительного контейнера, браузера, аккаунта или платного поискового API.
Модели и хостинг продолжают потреблять действующие ресурсы и тарифные лимиты.
Это метапоиск, а не собственный индекс всего интернета.

Ограничения: 500 символов запроса, до 20 результатов, до 5 доменов; 3 одновременно
выполняемых HTTP-запроса, максимум 32 ожидающих различных запроса; сетевой бюджет
9 секунд, короткий кэш 180 секунд (15 секунд для пустого/ошибочного ответа),
объединение одинаковых параллельных запросов. Результаты фильтруются по конкретной
модели товара и указанным доменам; реклама, служебные перенаправления и частные URL
не становятся ссылками результата. Фрагменты не получают статус прочитанной страницы.

OpenAI `web_search` в этом режиме является локально исполняемой функцией, а Kimi
search/search_pro используют этот же слой. Платный fallback автоматически не включается.
Для явно настроенной прежней интеграции можно задать `WEB_SEARCH_BACKEND=kimi`;
это отдельный платный режим для оператора, пользовательского выбора провайдера нет.

Выдача не вызывает автоматическое чтение восьми сайтов. Домашний браузер используется
для выбранных карточек российских магазинов. Обычные сайты читаются точечно через
`browse_page`, когда пользователь просит содержание или требуется конкретный первоисточник.
Российские карточки, короткие ссылки, доставка, продавец, максимум 20 текстов отзывов
и проверки предложений остаются в прежнем специализированном процессе.

Публичные поисковики могут вернуть CAPTCHA, 429, пустую или нерелевантную выдачу.
Это сохраняется как ограничение, не маскируется платным запросом или выдуманным результатом.
Кэш сокращает повторные обращения, но не гарантирует постоянную доступность.

## Границы адаптации

Действующие российские платежи, тарификация, home reader, инженерные навыки,
нормоконтроль, комплекты DOCX и локальная CAD-политика BitClient сохранены.
Облачные навыки доступны режиму Bit-Think в BitClient через общий сервер;
локальный Оркестратор остаётся отдельной функцией клиента.

| Процесс | Реализация/граница |
|---|---|
| Поиск, предметный анализ, статистика, Office, дизайн | Адаптированные инструкции + существующие инструменты/песочница/Студия |
| Почта, Drive, календарь, внешние API | Подключения владельца; без подключения — работа с предоставленными данными |
| MCP | Discovery, настоящая inputSchema, включённый владельцем список инструментов |
| Фоновые задачи | Существующая устойчивая очередь, fixed interval; не cron/event-триггеры |
| История и контекст проекта | Доступные беседы, файлы, инструкции; не новая общая wiki или полный Perplexity knowledge repo |
| Совет специалистов | Независимые ветви существующего Оркестратора, автоматический выбор по тарифу |
| Публикация сайта | Только реально доступный исполнитель и поручение; навык не создаёт универсальный хостинг |
| Исходящие звонки, HealthKit/EHR, Databricks | Штатных адаптеров нет. Подготовка/выгрузка либо отдельный разрешённый MCP |
| Музыка/видео | Текстовое планирование без заявления о готовой генерации; реальный результат требует генератора |
| Уведомления | Результат задачи в беседе; SMS/email/push требуют настоящего канала и поручения |
| Корзины/оплата в магазинах | Следующий этап; текущий продукт ищет, проверяет предложения и планирует закупку |

Полный машинный реестр всех 46 соответствий и контрольных сумм:
`backend/app/bot_core/computer_skills/adaptations.json`.
Исходные пользовательские материалы и их исполняемые скрипты на сервер не устанавливаются.

## Проверка

Регрессии охватывают native marketplace/engineering routing, включение и невключение
новых навыков, шаблоны только владельца, безопасное чтение ресурсов, отказы тарифа,
изоляцию фоновых задач, параллельное создание, сохранение фактических источников
под ограничением списка, бесплатный поиск без скрытых платных вызовов и без
автоматического обхода страниц. Legacy paid-provider contract проверяется отдельно.

Сборка фронтенда и типы клиента проверяются. UI-fixture проверяет разные размеры,
длинный ввод, клавиатуру, тему, шаблоны, поиск навыков и отсутствие перекрытий.
Это проверка интерфейса и инструментов; она не означает, что все генераторы,
коннекторы и ответы моделей проверены end-to-end на внешних аккаунтах.

всех 38 новых встроенных навыков и восьми личных шаблонов. VPN/nginx, конфигурации

интерфейс использует один ключ при повторе того же HTTP-запроса.

неизвестные MCP-вызовы получают сохранённую квитанцию до начала. Повтор завершённого
вызова возвращает прежний результат с явной пометкой; неопределённый вызов блокируется
до проверки во внешнем сервисе. Неизвестный MCP консервативно считается изменением.
