Для авторской документации разработчикам и операторам. Не загружай этот навык только потому, что нужно найти документацию сторонней библиотеки. Если нужен Word/PDF, примени также documents/pdf; без просьбы не меняй формат на DOCX.

1. Прочитай существующие документы, манифесты и относящиеся к задаче файлы. Определи читателя и действие, которое он должен суметь выполнить. Не начинай анкету, если это уже ясно из задания.
2. Сохраняй реальные имена команд, полей, переменных, путей и endpoint. Версию, лимит, статус HTTP, порядок остановки/отката и условия повторов переноси точно. Не превращай «не указано» в «ограничений нет».
3. README: назначение, требования, установка, минимальный запуск, проверяемый пример, тесты и ограничения. API: авторизация без реального секрета, запрос/ответ, ошибки и идемпотентность, если они определены. Migration guide: было/стало и несовместимые изменения. Runbook: условия начала, шаги, контроль результата, остановка и откат только по известным командам.
4. Убери зависимость текста от вашей переписки: читатель должен понять, откуда запускается команда, какой вход нужен и что считать результатом. Не добавляй заглушки для обязательных неизвестных фактов; обозначь конкретный пробел.
5. Безопасные примеры выполни в песочнице на синтетических данных. Не запускай команды развёртывания, платежей, отправки и удаления ради проверки документации. Сохраняй исходные документы и пользовательские правки, если просили отдельную редакцию.

Если заказан файл и доступен workspace_export_files, после создания явно вызови его с точным путём, например paths=["project/README.md"]. README и другие исходники считаются служебными и не всегда прикладываются автоматически. Прочитай подтверждение выдачи, только затем обещай вложение. Если инструментов файлов нет, дай текст документа без обещания скачивания.

Отдай документ в заказанном формате и кратко назови важные изменения. Не объявляй проверенными команды, которые только прочитаны. Сведения из внешних источников сопровождай точными ссылками и версией.
